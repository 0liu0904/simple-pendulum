# 单摆物理模拟器（Simple Pendulum Simulation）

## 1. 项目介绍

本项目是一个基于 HTML5 Canvas 与原生 JavaScript 实现的**单摆物理模拟器**。

- 使用简谐振动角加速度公式进行物理计算：

  ```text
  θ'' = −(g / L) · sin(θ)
  ```

- 采用固定步长积分与 `requestAnimationFrame` 驱动动画循环，保证不同刷新率下的运动一致性。
- 深灰科技风背景（`#1a1a24`），摆线带冷色光效，摆球带有微弱发光与运动拖尾。
- 初始参数：摆长 `L = 200px`，重力加速度 `g = 9.8`，初始摆角 `45°`。
- 交互方式：打开页面后自动摆动；按 `空格` 暂停 / 继续，按 `R` 重置。

### 运行方式

无需安装任何依赖，直接双击 `index.html`，使用浏览器打开即可运行。

## 2. 人机协同三反思

### ① AI 生成代码的优势

1. **起步快**：AI 能根据自然语言需求快速生成完整的项目骨架，省去从零搭建 HTML、Canvas 渲染循环和物理积分的时间。
2. **结构清晰**：代码通常按配置、状态、物理计算、绘制、主循环分层组织，便于阅读和二次修改。
3. **细节完善**：AI 能主动补充高分屏适配、固定步长积分、暂停/重置交互、拖尾光效等容易被忽略的工程细节。
4. **便于学习**：生成的代码带有注释和清晰的物理公式对应关系，有助于理解单摆模型与动画循环的实现方式。

### ② 人机协同过程遇到的困难

1. **需求描述与实现细节之间存在差距**：例如“摆长 200px、重力 9.8”并不能直接同时作为像素和物理单位使用，需要引入比例尺（100px = 1m）才能得到自然、流畅的摆动效果。
2. **物理正确性与视觉效果需要权衡**：完全真实的物理参数可能导致摆动过慢，而过度调整参数又会偏离题目要求，需要在两者之间找到平衡。
3. **视觉风格难以用文字精确表达**：“科技感”“微弱发光”等描述较主观，需要多轮调整颜色、光晕半径、透明度和拖尾长度。
4. **设备差异**：不同屏幕尺寸、刷新率和像素密度会影响显示效果，需要额外处理画布自适应与固定时间步长。
5. **AI 生成代码需要人工审查**：部分实现可能看似合理，但仍需检查公式符号、单位换算、边界情况和交互逻辑。

### ③ 本次人机协同学习收获

1. **学会了如何把模糊需求拆解为可执行的工程问题**：将“做一个单摆”拆分为物理模型、时间步长、坐标换算、渲染分层和交互控制。
2. **加深了对物理仿真与动画循环的理解**：认识到固定步长积分、`requestAnimationFrame`、单位换算对动画稳定性的重要性。
3. **体会到 AI 是协作工具而不是替代品**：AI 可以快速产出初稿，但需求判断、效果验收和细节修正仍需要人来完成。
4. **提升了代码审查与迭代能力**：通过阅读、运行和修改 AI 生成的代码，逐步定位问题并优化实现。
5. **积累了可视化项目经验**：掌握了 Canvas 渐变、光晕、拖尾、自适应画布等常用视觉表现手法。
